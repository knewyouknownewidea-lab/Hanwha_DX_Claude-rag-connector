# 구매·협력사 AI 분석 플랫폼 (시연판)

협력사·구매조달·원가-계약·자재-공급 데이터를 한 화면에서 관리하고, 자연어로 분석을 요청하면 AI가 결과 형식을 추천해 바로 보여 주는 웹 플랫폼입니다.

**로그인 → 데이터 관리(왼쪽)에서 찾기 → 행을 누르면 오른쪽에 상세 → 왼쪽 아래 'AI에게 질문하기' → 분석 결과(오른쪽)에서 형식·보기 설정 변경 → 엑셀로 내보내기**

현재 버전: v0.4.0 (변경 내용은 `CHANGELOG.md`)

> 모든 업체명·품목·수치·시세·임금·경쟁사·기사는 시연용 가상 데이터(SAMPLE)이며 실제 자료가 아닙니다.

## 실행 방법

설치 없이 보기: `dist/index.html`을 브라우저로 열면 바로 동작합니다(규칙 기반 데모 모드).

개발 환경 (Node.js 18 이상):

```bash
npm install
npm run dev        # 소스 변경 감시 빌드 + http://localhost:5173
npm start          # 한 번 빌드 후 서버 실행
npm run build      # dist/index.html(한화엔진 표기), dist/artifact.html(중립 표기) 생성
```

처음 열면 간이 로그인 화면이 나옵니다. 이름만 넣으면 들어가며(사번·부서는 선택), 발표 때는 **시연 계정으로 바로 시작**을 누르면 됩니다. 비밀번호를 받지 않는 시연용 구분이며 보안 인증이 아닙니다.

## 화면 구성 (v0.3.2)

- **상단 바:** 한화엔진 로고·브랜드 │ 플랫폼 이름, 데이터 상태(SAMPLE/업로드·기준일·저장 상태), 질문 해석 방식(규칙 기반/LLM), 결제 알림 종, 데이터 불러오기, 샘플 데이터로 되돌리기, 사용자 메뉴(관심 목록·사용 안내·저장된 업로드 데이터 삭제·로그아웃). 1024px 이하에서는 두 줄로 나뉩니다.
- **왼쪽 데이터 관리:** 협력사 평가 카드(도넛·항목별 막대, 오른쪽 위 구석에 '근거' 버튼과 작은 처리 단계 표시), 4개 데이터 탭과 하위 보기
  - 협력업체: 협력사 목록 (상세에 공급 부품 분류 경로·등급 변동 이력·관련 직종 임금)
  - 구매조달: 발주 목록 · 대금 결제 일정
  - 원가-계약: 계약 단가 · 원자재 시세 · 인건비 동향
  - 자재-공급관리: 재고·공급 · 경쟁사 공급 동향 · 업계 동향
  - 모든 탭: 검색, 빠른 필터(★ 관심만 포함), 상세 필터(부품 분류 4단계 포함), 두 방향 정렬, 20/50/100행 페이지 나누기, 엑셀 내보내기
- **오른쪽 분석 결과:** 표에서 고른 협력사·발주·계약·부품의 선택 정보(머리의 아이콘으로 접고 펼침, 챗봇 결과가 나오면 자동으로 접힘), 결과 형식 4종(협력사 비교표·데이터 시각화·종합 평가 카드·분석 보고서), 보기 설정·프리셋, 분석 이력(검색·이름 바꾸기·고정·삭제), 내보내기(엑셀·CSV)
- **AI 챗봇:** 왼쪽 아래 'AI에게 질문하기' 버튼으로 여닫는 떠 있는 창 (이동·크기 조절, ⋯ 메뉴에 투명도·위치 초기화·대화 지우기)
- 처음 로그인하면 3단계 사용 안내가 뜹니다(건너뛰기 가능, 사용자 메뉴에서 다시 보기).
- 1180px 이하는 데이터 관리/분석 결과 탭 전환(행을 누르면 분석 결과 탭으로)과 하단 시트 챗봇

## 이 브라우저에 저장되는 것

서버에는 아무것도 저장하지 않습니다. 저장에 실패해도(사생활 보호 모드·용량 초과) 화면은 계속 동작하고 안내가 뜹니다.

| 내용 | 저장소 | 키 (`procure-ai:` 뒤) | 범위 |
|---|---|---|---|
| 대화 내역, 분석 결과·이력(최대 50건, 이름·고정) | localStorage | `u:{사용자}:session.v3` | 사용자별 |
| 보기 설정·내 프리셋 | localStorage | `u:{사용자}:view-settings.v2` | 사용자별 |
| 관심 협력사·부품, '관심 항목 맨 위', 결제 '확인함' 표시 | localStorage | `u:{사용자}:prefs.v1` | 사용자별 |
| 첫 사용 안내를 봤는지 | localStorage | `u:{사용자}:onboarded.v1` | 사용자별 |
| 업로드 데이터 (dataId·기준일·출처 파일명 포함) | IndexedDB `procure-ai` / `uploads` | `u:{사용자}:uploads` | 사용자별 |

- v0.2.0 때 저장된 대화·결과·보기 설정은 처음 로그인한 사용자에게 옮깁니다.
- 로그아웃할 때 "이 브라우저에 저장된 내 데이터도 지우기"를 고르면 그 사용자의 위 항목을 모두 지웁니다(공용 PC 권장).
- 비밀번호와 API 키는 브라우저에 저장하지 않습니다.

## 데이터 추가 방법

1. 상단 **데이터 불러오기**, 각 탭의 **불러오기**, 하위 보기의 **불러오기** 중 하나를 누릅니다.
2. 데이터 종류를 고르고 CSV(첫 줄 열 이름) 또는 JSON 배열 파일을 올립니다. **빈 양식 받기**로 열 이름이 채워진 양식을 받을 수 있습니다.
3. 열 이름은 필드명·한글 이름·별칭으로 자동 연결됩니다(예: `업체ID`, `협력사id`, `supplierId`). 대화상자의 **필드 안내**를 참고하세요.
4. 형식 검사 결과를 확인합니다. 오류는 "무엇이 잘못됐는지 → 어떻게 고치는지"로 보여 주며, 행 번호는 파일을 엑셀로 열었을 때의 행 번호입니다. 오류가 있는 행은 반영하지 않습니다.
5. **병합**(같은 키면 새 값으로 바꾸고 나머지는 그대로) 또는 **교체**(그 데이터 전체를 바꿈)로 반영합니다. 반영하면 지표를 즉시 다시 계산하고 이 브라우저에 저장합니다. 떠 있는 결과에는 "다시 분석" 안내가 뜹니다.

| 데이터 | 한 행을 구분하는 열 | 주요 열 |
|---|---|---|
| 부품 분류(BOM) | 엔진 모델 + 품목코드 | 엔진 모델, 대부품, 중부품, 소부품, 품목코드 |
| 원자재 시세 | 기준월 + 원자재 + 시장 | 기준월(YYYY-MM), 원자재, 시장(국제/국내), 가격, 단위, 통화, 출처 |
| 환율 | 기준월 + 통화 | 기준월, 통화, 원화 환율, 출처 |
| 인건비 | 기준월 + 대·중·소분류 | 기준월, 대분류, 중분류, 소분류, 월평균 임금(원), 출처 |
| 경쟁사 공급 동향 | 경쟁사 + 품목코드 + 공급처 | 경쟁사, 품목코드, 공급처, 수요 내용, 시기, 확인일, 출처, 출처 링크 |
| 업계 동향 | 날짜 + 제목 | 날짜, 제목, 요약, 관련 품목, 관련 원자재, 출처, 출처 링크 |

연결 키: 협력사 `supplierId`, 품목 `itemCode`, 발주 `poNo`, 계약 `contractId`. 경쟁사 실명은 출처 링크와 날짜가 있는 공개 자료(공시·보도·업체 홈페이지)로만 올려 주세요. 링크가 없으면 "출처 링크 없음" 경고가 붙습니다.

## 계산 규칙

**대금 결제 일정** (`src/lib/payments.ts`의 `PAYMENT_RULE`, 지원 형식은 `SUPPORTED_TERMS` 한 곳에서 관리)

- 기준: 입고일. 아직 입고 전이면 납기 예정일("납기 예정"으로 표시)
- 해석하는 결제조건: `월말 마감 N일`(입고한 달 말일 + N일), `월말 마감 익월 D일`(입고 다음 달 D일), `입고 후 N일`·`검수 후 N일`
- 해석하지 못한 조건(예: T/T 선적 후 30일 — 선적일 데이터 없음, 분할 결제)과 계약이 없는 발주는 날짜를 추정하지 않고 "결제조건 확인 필요"로 표시하고 이유를 함께 보여 줌
- 상태: 7일 이내 **임박**, 30일 이내 **예정**, 지난 14일 이내 **지급 확인 필요**(지급 실적 데이터가 없어 지급 완료·지연은 판단하지 않음), 납기가 지났는데 입고 전이면 **입고 대기**
- 금액 = 발주 수량 × 발주 단가, 통화별로 따로 합계(환율로 합치지 않음)
- 헤더 종 배지 = 임박 + 지급 확인 필요 중 '확인함' 표시하지 않은 건수 ('확인함'은 지급 완료 처리가 아님)

**원자재 시세** (`src/lib/market.ts`)

- 국제 시세(USD/톤)는 같은 달 환율로 원/kg로 바꿔 국내 시세(원/kg)와 같은 축에서 비교: `USD/톤 × 원/달러 ÷ 1,000`
- 표: 최근 값, 전월 대비, 전년 같은 달 대비, 3개월 추세. 품목별 주요 소재 변동률과 계약 단가 변동률은 수치만 나란히 보여 주고 원인 판단 문장은 쓰지 않음

**인건비 동향:** 소분류 월평균 임금의 전년 같은 달 대비 상승률, 상위 분류 평균과 비교. 협력사 공정(주조·단조·가공·배관 등)을 관련 직종 소분류와 연결해 협력사 상세에 표시

## AI API 연결 방법

### 구매 DB RAG 연결 (v0.4.0)

기존 **AI에게 질문하기** 창의 **질문 방식 → 구매 DB RAG**를 선택하고 답변 모델을 고릅니다.
질문은 웹 서버의 `/api/rag/jobs`를 거쳐 별도로 실행한 구매 RAG 게이트웨이에 전달되며,
완료된 답변과 `[E1]` 출처·원본 DB 참조를 대화창에 표시합니다.
서버 환경변수 `RAG_ORIGIN`(게이트웨이 주소)과 `RAG_GATEWAY_TOKEN`(32자 이상 비밀 토큰)을 설정해야 합니다.
토큰과 내부 게이트웨이 주소는 브라우저에 보내지 않습니다.

RAG는 별도 구매 DB 기준이며, 화면에서 선택한 `SUP-001`·품목 코드·업로드 데이터를 자동으로 사용하지 않습니다.
**웹 데이터 분석** 모드는 기존 기능을 유지합니다. 자세한 실행 순서·설정·API 계약·테스트는 [docs/RAG.md](docs/RAG.md)를 확인하세요.
`dist/index.html`을 파일로 열거나 정적 호스팅만 사용하는 경우에는 RAG 중계 서버를 실행할 수 없습니다.

### 기존 질문 해석 LLM

LLM은 **질문 해석에만** 쓰고, 수치 계산·업체 비교·근거 문장은 코드가 데이터로 만듭니다. LLM 응답은 목록에 있는 품목코드·업체ID만 남기도록 검증합니다.

```bash
ANTHROPIC_API_KEY=발급받은_키 LLM_MODEL=claude-haiku-5-5 npm start
```

- 키는 서버 환경변수로만 읽고 브라우저 코드에 넣지 않습니다(`server/index.mjs`의 `/api/ai/interpret`).
- 연결되면 상단 상태가 "LLM 사용 가능"으로 바뀌고 **LLM 해석** 모드를 켤 수 있습니다.
- 키가 없으면 규칙 기반 해석으로 동작하고, 답변마다 "규칙 기반 데모 응답" / "LLM 해석 · 계산은 코드"로 구분해 표시합니다.
- 회사가 지정한 다른 AI 도구로 바꿀 때는 `src/ai/llm.ts`의 provider와 `server/index.mjs`의 `interpret()`만 교체하면 됩니다.

## 구조

| 계층 | 위치 |
|---|---|
| 데이터 | `src/data/` (타입 `types.ts`, 업로드 필드 정의 `schema.ts`, 샘플) |

| 계산 | `src/lib/metrics.ts`(지표), `evaluation.ts`(평가 점수), `analysis.ts`(질문 유형별 분석), `payments.ts`(결제 일정), `market.ts`(시세·임금), `bom.ts`(부품 분류), `kpi.ts`(빠른 필터 정의) |
| 내보내기 | `src/lib/xlsx.ts`(패키지 없는 .xlsx 작성), `src/lib/exporters.ts`(결과·표 → 시트) |
| AI | `src/ai/intent.ts`(규칙 해석), `src/ai/llm.ts`(LLM 연결), `src/ai/agent.ts`(질문 처리 흐름) |
| 저장 | `src/platform/storage.ts`(localStorage), `idb.ts`(IndexedDB), `users.ts`(간이 로그인·이전·로그아웃) |
| 템플릿 | `src/templates/registry.ts`, `presets.ts` + `src/components/templates/*` |
| UI | `src/App.tsx`, `src/components/*` (상단 바 `Topbar.tsx`, 선택 정보 `SelectionDetail.tsx`, 챗봇 `ChatWidget.tsx`, 분석 이력 `HistoryPanel.tsx`, 하위 보기 `subviews/*`) |
| 브랜드 | `src/brand/*`, `src/components/Brand.tsx` |

평가 기준은 `src/lib/evaluation.ts`의 `EVAL_CONFIG`(가중치·등급 구간·관리 기준)만 바꾸면 됩니다. 현재 값은 **내부 평가 기준 예시 v0.1 (DEMO)**이며 ISO 9001 공식 점수가 아닙니다.

## 미구현 · 한계

- 실제 사내 ERP·QMS·지급 실적, 시세·임금 공공 데이터 자동 연동 없음 (파일 업로드로 대체)
- 챗봇은 새 데이터(결제 일정·시세·인건비·경쟁사·업계 동향)에 대한 질문에 아직 답하지 않음 (각 하위 보기 화면에서 확인)
- 간이 로그인은 사용자 구분용이며 보안 인증이 아님. 모든 저장은 이 브라우저에만 되고 팀과 공유되지 않음
- 표 열 제목 고정(세로 스크롤 시)은 가로 스크롤과 함께 쓰기 어려워 페이지 나누기로 대신함
- 정성 평가 자동 생성 없음 — "기록된 데이터 그대로" 원칙에 맞춰 근거 설명만 만듦
- 기간 조건은 "최근 N개월/N년"만 해석, 복잡한 조건 조합은 일부만 지원
- Vite·Tailwind·Recharts 대신 esbuild·직접 작성한 CSS·SVG 차트를 사용 (개발 환경에서 패키지 저장소에 접속할 수 없어 설치 가능한 범위로 구성). 엑셀 파일도 패키지 없이 직접 만듦
